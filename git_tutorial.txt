GIT TUTORIAL:
BASIC
1. To know git version / installability just enter git --version.

2. To know the configuration.
git config --global --list
git config --local --list

3. To config things.
	git config --global user.name “DevCal2022”
	git config --global user.email “devkag1994@gmail.com”

4. To clone any repo.
	git clone repo_ url

5. If we want to copy repo locally other than cloning. we need to perform several commands:
	git init / git init project-directory_name
	git remote add origin repo_url
	git fetch origin
	git checkout main-branch

6. To create a new branch locally we need to perform.
	git checkout -b branch-name

7. To add files in staging.
	git add .             # add all the files from cwd.
	git add filename_with_path.

8. To commit something to local we need to perform 
	git commit -m “message about commit”

9. To push code into remote with a specific branch.
	git push origin branch_name

10. To pull into a local from a specific branch.
	git pull origin branch_name

11. To get status.          git status


Branch 
12. To rename the branch we just do like that:
	git branch -m new_name (In this it takes current branch as by default old_branch)
	git branch -m old_branch_name new_branch_name

13. To configure the default branch using CLI. 
	git config --global init.defaultBranch “branch name”
	
14. To shortcut the add and commit step in single command by using below way:
	git commit -am "commit message"

15. If we want to reset the staging file to working directory:
	git reset HEAD file_name

16 If we want to remove modified changes in a particular file.
	git checkout -- file_name

17. If we want to cancel all modified changes.         git stash

18. To change the file name using git command.
	git mv current_file_name new_file_name
(if we are done using this we are pushing the file in the staging area by default).

19. If we changing the file name using command line of OS then need to add into staging by 
      git add -A and if we rename it through OS file manager then fix it by git add file_name.

20. How to delete file using git git rm file_name 
      (it is by default put into a staged area to fix it; we can commit the changes or untracked it by   using step 15).

21. If we delete the file using file manager or command line it directly puts this into the working
      directory area we need to follow the same steps as we follow in step 19.
	






HISTORY
22. To see history:
	git log
	git log --abbrev-commit         #gives a commit id
	git log --oneline
	git log --oneline --graph --decorate 
(shows the branching flow in graphical manner).
	
git log range_of_commit_ids
	git log --since="3 days ago" (prompt)
	git log -- filename                   (To get commit history for specific file)
	git log --follow -- filename     (Gives all the commit history to rename the file)
	git show commit id                
(Show information related to that commit message)

23. To alias any command for example git history
	"git log --all --oneline --graph --decorate"
	
git config --global alias.hist “log --all --oneline --graph --decorate” 
	(this will store into .git-config file if we use global user level configuration)
	(if we use local then it will store into repository/.git/config file)
	git hist

The format of file
		a. Write single expression in one line
			Specific File Name: text.txt
			File Pattern: *.ext

Install and Configuring P4Merge
25. To configure P4Merge (visual tool to check difference and merge)
	1. Go to the Downloads page of Perforce website, and in the search bar write: p4merge.

2. Choose the p4merge for Linux platform and download it 
(note that you can skip the registration).

3. Once downloaded extract it and copy the contents of the folder to a new folder /opt/p4merge:
		a) gunzip p4v.tgz
		b) tar xvf p4v.tar
		c) sudo mkdir /opt/p4merge

d) I have downloaded it to /home/devendra/Downloads and the "extracted" p4merge folder was p4v-2019.1.1830398, so in my case the command was:
			
sudo mv /home/devendra/Downloads/p4v-2019.1.1830398/* /opt/p4merge

4. Create a symbolic link to the p4merge executable with the command:
sudo ln -s /opt/p4merge/bin/p4merge /usr/local/bin/p4merge

5. Add the following commands to git's "global config settings" so p4merge will be used as both git's difftool & mergetool:
		
git config --global merge.tool p4merge 
		git config --global mergetool.p4merge.path /usr/local/bin/p4merge
		git config --global mergetool.prompt false
		
git config --global diff.tool p4merge
		git config --global difftool.p4merge.path /usr/local/bin/p4merge
		git config --global difftool.prompt false
		
In order to see diff's (between Working directory to the staging area, for instance) you can now use the command:git difftool that will open the p4merge GUI to be used.
		
If you want to configure it in local then just replace --global with --local



Comparison
26. To compare the changes:
1. Working Directory vs Staging:
		a. git diff (cli)
		b. git difftool (graphical tool)
	
2. Working Directory vs Local git repo:
		a. git diff HEAD
		b. git difftool HEAD
	
3. Staging vs Local git repo:
a. git diff --staged HEAD
		b. git difftool --staged HEAD

27. To compare the directory but limiting to single file then we need to use:
	a. git diff -- file path
	b. git difftool -- file pathname	

28. To compare between two commits:
	a. git diff r1 r2 (r1: reference commit id 1, r2: reference commit id 2)
	    git diff r1 HEAD (compare reference 1 to last commit)
	    git diff HEAD HEAD^ 
(compare last commit and just one commit before last commit)
	
b. git difftool r1 r2
	     The same two commands can also be excute using these git difftool..

29. To compare Local and Remote:
	git diff local_branch remote_branch
	git difftool local_branch remote_branch

30. To delete git branch locally
git branch -d “branch_name” 			  	










Merge & Rebase
31. To merge any branch into main branch (fast forward):
	git merge branch_name_to_be_merged  [Fast Forword Merge]

	(by default it merge to current branch)
(all the commits which are on the new branch will move to the main branch no branching will show. This can only be possible when nothing is committed on the main branch after we created our branch.)
	
	git merge branch_name_to_be_merged –no-ff [No Fast Forword]
	
(In this branching is shown to us and merge commit is placed on main branch)

32.  To merge any branch with recursive strategy:
	git merge branch_name -m “commit message” [Automatic Merge]

33. To resolve the conflicts we can do in two ways:
Through the editor.
Through the mergetool
git mergetool

34. To stop merge when conflicts came:
	git merge –abort

35. To rebase the Feature Branch we need to use:
git rebase source_branch 
(this command should execute from branch whose base we want to change)

36. To abort rebasing any branch when there is conflict at the time of rebasing.
	git rebase –abort

37. To rebase the local branch from github remote branch just execute this branch:
	git pull –rebase origin/master

	











G. Stashing
38. To apply stashed file into our WD we need to execute:
git stash apply
git stash list (gives list of stash)
git stash drop (drop stash references)

39. To stash untracked file we have two options:
git stash -u
git stash pop (this will do stash apply  and stash drop simultaneously)

40. To save the stash with message:
	git stash save “commit message”
	git stash show “stash{index}”  [it show the details about that stash]

41. To apply any specific stash:
	git stash apply stash@{reference}
	git stash drop stash@{reference}  [to drop specific stash]

42. To clear all stash          git stash clear

43. To put all stash into a branch follow this steps:
git stash -u
git stash branch branch_name
git add .
git commit -m “message”
To apply this stash merge this into your branch.

H. Tagging
	44. To add any tag to Head:
		git tag Tag_name [this is called Lightweight tag]
		git tag –list [it Gives list of tags on our repo]
		git tag –delete tag_name [it deletes tag from repo]
		git show tag_name [it shows the details of that tag]
	
45. To add annotated Tag:
	git tag -a tag_name  [it will Open the editor to put some message related to tag]
git tag tag_name -m “tag message”  [another method to add tag and message]

46. To update the commit message on local:
	git commit –amend
47. To compare between two tags:
	git diff starting_tag_name end_tag_name
	git difftool starting_tag_name end_tag_name

48. Add tag to specific commit:
	git tag -a tag_name reference_commit

49. Update any tag:
	git tag -a tag_name -f reference_commit 

50. If we want to push this local tags to remote repo then we can do that:
	git push origin tag_name 
(if related commit is not pushed to remote then it will pushed that one as well)

51. If we want to push all tags then synchronize the branch with extra tags:
	git push origin branch_name –tags

52. If we want to delete any tag from remote or not want to push particular tag:
	git push origin : tag_name

I. Reset & Reflog:
	53. If we want to time travel backward:
		git reset HEAD^ / HEAD^n
	
	54. If you want to see the work history:
		git reflog
